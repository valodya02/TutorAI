# План работ TutorAI

## Текущее состояние

Рабочий MVP на FastAPI + vanilla JS: генерация плана/модулей/теории через Groq, режим курса по PDF, сохранение курсов в JSON. Проект рассчитан на локальное личное использование одним пользователем; auth, квоты и публичное развёртывание не являются целями. Тестов, линтеров, Docker и CI нет. Зависимости описаны в `requirements.txt`; runtime-данные и секреты исключаются из git. Подробности — `docs/ARCHITECTURE.md`.
Приоритеты: **P0** — безопасность и блокеры запуска, **P1** — архитектура и тесты, **P2** — качество и DX, **P3** — развития.

## P1 — архитектура и тесты

- [ ] **P1-1: Разделить `app.py`** — вынести промпты, LLM-клиент, роуты курсов и схемы в отдельные модули; убрать глобальный `Groq` при импорте. Готово: `app.py` только собирает приложение; импорт без ключа не падает. Файлы: `backend/app.py` → `backend/llm.py`, `backend/prompts.py`, `backend/courses.py`, `backend/schemas.py`.
- [ ] **P1-2: Проверять ответы LLM** — явные Pydantic-схемы для плана/модулей/выбора разделов, обработка `selected` не-списка и пустого TOC без 500. Готово: некорректный JSON модели даёт 502 с понятным текстом; пустой учебник — 422. Файлы: `backend/app.py:153-161`, `backend/book_plan.py:25-38,66-72`.
- [ ] **P1-3: Слой хранения** — вынести чтение/запись курсов и книг в репозиторий с единой обработкой битых JSON и блокировками. Готово: битый файл не роняет список, а логируется и пропускается. Файлы: `backend/app.py:216-273`, `backend/books.py:19-35`.
- [ ] **P1-4: Тесты backend** — pytest + httpx: health, валидация, mock Groq, парсинг TOC, CRUD курсов, path traversal. Готово: `pytest -q` зелёный, покрытие ключевых роутов ≥70%. Файлы: `tests/`, `pyproject.toml`.
- [ ] **P1-5: Устойчивость фронтенда** — таймауты/`AbortController`, корректный разбор не-JSON ответов, отмена устаревших запросов, единая обработка `detail`-объектов. Готово: медленный/упавший запрос показывает понятную ошибку, UI не зависает. Файлы: `frontend/js/api.js:1-6`, `frontend/js/books.js:5-12`, `frontend/js/app.js`.
- [ ] **P1-6: E2E-тест основного сценария** — Playwright: цель → план → модули → теория → сохранение → открытие. Готово: тест проходит на mock-сервере LLM. Файлы: `e2e/`, CI.
- [ ] **P1-7: Идемпотентность и защита от гонок** — не перезаписывать чужой курс молча, версионировать (`updated`) и обрабатывать конфликт 409. Готово: два таба не теряют изменения без предупреждения. Файлы: `backend/app.py:246-251`, `frontend/js/app.js:91-92,139-141`.

## Открытые вопросы

1. Приложение задумано как локальное однопользовательское или как публичный сервис? От этого зависит приоритет P0-3 (auth) и выбор хранилища.
2. Где будет развёртывание (локально, VPS, serverless)? Лимиты PDF и таймауты LLM зависят от платформы; сейчас неизвестно.
3. Кому принадлежит ключ Groq и кто оплачивает токены? Нужны ли лимиты на пользователя и бюджетные алерты?
4. Допустимо ли отправлять тексты целей и фрагменты загруженных PDF в Groq? Нужно ли согласие/уведомление о приватности?
5. Есть ли требования к авторским правам на загружаемые учебники и хранению их текста?
6. Нужна ли поддержка сканов без текстового слоя (OCR) или достаточно отклонять их, как сейчас?
7. Целевой масштаб: десятки курсов или тысячи? Когда нужен SQLite/Postgres (P3-2)?
